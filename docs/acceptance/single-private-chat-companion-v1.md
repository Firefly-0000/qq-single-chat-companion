## 1. 验收目标与范围

交付一个 Windows 桌面程序，包含 GUI 前端和 Python 后端。后端仅通过屏幕识别和键鼠输入操作已经登录的 QQ 客户端，不读取 QQ 数据库、不注入进程、不 Hook、不逆向协议，也不使用 QQ Bot 协议。

本版本只服务一个固定的 QQ 私聊对象。GUI 必须提供 `目标用户名称` 输入框。程序必须先由用户手动打开目标私聊，再绑定当前对话；程序不得自行搜索联系人、切换联系人或进入群聊。

AI 回复必须通过独立 API Key 调用 DeepSeek 官方兼容 API。程序不要求识别表情包、图片或表情含义，但必须检测对方是否发送了新的非文字消息事件。

### 非目标

- 不处理群聊、频道或多个联系人。
- 不识别表情包、图片、语音、文件或红包内容。
- 不使用 OneBot、NapCat、QQ 协议库或内存读取。
- 不在未经用户批准时自动向任何对象发送消息。
- 不承诺成为医疗、法律、金融或心理治疗建议系统。

## 2. 前置条件

- Windows 10 或 Windows 11。
- 腾讯 QQ 桌面客户端已安装并已由用户手动登录。
- 目标私聊已由用户手动打开并保持可见。
- 屏幕缩放、分辨率、主题和 QQ 窗口尺寸已保存为固定配置。
- DeepSeek API Key 有效，并已通过 GUI 或环境变量提供。
- 程序运行时 QQ 窗口未被遮挡，系统未锁屏。
- 测试联系人、测试消息和测试 API Key 已准备。

## 3. 功能验收标准

| ID | 需求 | 验收标准 | 优先级 | 结果 |
|---|---|---|---|---|
| AC-GUI-001 | 目标用户名称输入 | Given GUI 首次打开，When 用户查看绑定区，Then 存在必填的 `目标用户名称` 输入框，空值或全空格时“绑定当前对话”按钮不可用 | P0 | NOT_RUN |
| AC-GUI-002 | 绑定目标会话 | Given 用户已打开目标私聊并输入名称，When 点击“绑定当前对话”，Then 程序识别 QQ 当前聊天标题，并按忽略首尾空格和全半角空格的规则与输入名称比较 | P0 | NOT_RUN |
| AC-GUI-003 | 错误会话拦截 | Given 输入名称与当前聊天标题不一致，When 点击绑定，Then 程序不得启动识别或发送，显示绑定失败原因并停留在未绑定状态 | P0 | NOT_RUN |
| AC-GUI-004 | 运行控制 | Given 程序已绑定目标会话，When 用户点击启动、暂停、停止或急停，Then 对应状态在 1 秒内显示，停止和急停后不得再发送新消息 | P0 | NOT_RUN |
| AC-GUI-005 | 配置管理 | Given 用户查看设置页，When 配置 DeepSeek API Key、Base URL、模型、轮询间隔和回复长度，Then 配置可保存、重新加载并恢复，API Key 输入框必须遮蔽明文 | P0 | NOT_RUN |
| AC-GUI-006 | 上下文查看 | Given 已产生对话记录，When 用户打开上下文页，Then 可按时间顺序查看对方消息、AI 回复和非文字消息事件，并可清空或编辑上下文 | P1 | NOT_RUN |
| AC-QQ-001 | 窗口范围限制 | Given 程序处于运行状态，When 执行截图、点击、粘贴或发送，Then 所有操作坐标必须位于已绑定 QQ 窗口边界内 | P0 | NOT_RUN |
| AC-QQ-002 | 禁止切换联系人 | Given 程序处于运行状态，When 进行消息检测或回复，Then 程序不得点击联系人列表、搜索框或任何会切换当前会话的控件 | P0 | NOT_RUN |
| AC-QQ-003 | 标题变化保护 | Given 程序已绑定目标名称，When 当前聊天标题 OCR 结果不再匹配，Then 程序在 2 秒内进入暂停状态且不得发送任何消息 | P0 | NOT_RUN |
| AC-QQ-004 | 群聊保护 | Given 当前窗口被识别为群聊、频道或非目标私聊，When 检测循环继续，Then 程序必须跳过处理并记录阻断原因 | P0 | NOT_RUN |
| AC-QQ-005 | QQ 边界 | Given 程序运行中，When 检查进程和行为，Then 不存在 QQ 数据库读取、协议逆向、进程注入、Hook、Cookie 读取或 QQ 文件修改 | P0 | NOT_RUN |
| AC-MSG-001 | 新消息检测 | Given 已绑定窗口处于空闲状态，When 对方发送一条新文字消息，Then 程序在该消息可见后 2 秒内产生唯一的待回复事件 | P0 | NOT_RUN |
| AC-MSG-002 | 发送方判断 | Given 当前消息区发生变化，When 最后一条气泡位于对方一侧，Then 允许生成回复；When 最后一条气泡属于自己，Then 不得触发回复 | P0 | NOT_RUN |
| AC-MSG-003 | 非文字事件 | Given 对方发送表情、图片或其他不可 OCR 的文字内容，When 检测到新气泡但没有可识别文本，Then 记录为 `non_text_event`，不识别其含义，默认不自动回复 | P0 | NOT_RUN |
| AC-MSG-004 | 重复检测保护 | Given 同一画面被连续截取多次，When 消息指纹未变化，Then 只能产生一个待回复事件，不得多次调用 DeepSeek | P0 | NOT_RUN |
| AC-MSG-005 | 连续消息合并 | Given 对方在 3 秒内连续发送多条文字消息，When 程序尚未开始生成回复，Then 应合并为一次上下文请求并只生成一轮回复 | P1 | NOT_RUN |
| AC-CTX-001 | 初始上下文 | Given 用户成功绑定目标会话，When 程序首次启动，Then 应读取当前可见的最近对话文字并建立初始上下文 | P0 | NOT_RUN |
| AC-CTX-002 | 上下文持久化 | Given 程序已处理消息，When 程序正常退出并重新启动，Then 最近对话、摘要和最后处理指纹可以恢复 | P0 | NOT_RUN |
| AC-CTX-003 | 单会话隔离 | Given 当前版本只绑定一个联系人，When 生成本次请求，Then 上下文中不得包含任何其他联系人或群聊内容 | P0 | NOT_RUN |
| AC-CTX-004 | 上下文长度控制 | Given 历史消息超过配置上限，When 构造 DeepSeek 请求，Then 程序发送“长期摘要 + 最近 N 轮消息”，且总长度不超过配置的 token 或字符上限 | P1 | NOT_RUN |
| AC-CTX-005 | 用户管理 | Given 用户选择清空上下文，When 确认操作，Then 后续回复不得引用被清空的历史；清空动作必须写入本地审计日志 | P1 | NOT_RUN |
| AC-API-001 | DeepSeek 兼容配置 | Given 用户配置 DeepSeek API Key，When 使用官方兼容 Base URL 调用，Then 请求成功并返回非空文本；模型名必须可配置且不得硬编码 | P0 | NOT_RUN |
| AC-API-002 | 密钥保护 | Given API Key 已保存，When 查看日志、GUI 回显和错误信息，Then 不得出现完整或可还原的 API Key | P0 | NOT_RUN |
| AC-API-003 | API 失败保护 | Given DeepSeek 返回超时、401、429 或 5xx，When 生成回复失败，Then 不得发送空消息或报错文本；401 进入暂停并要求用户处理 | P0 | NOT_RUN |
| AC-API-004 | 重试边界 | Given 发生可重试的临时错误，When 程序自动重试，Then 最多重试 3 次并使用退避；发送已经尝试后不得重复调用导致重复回复 | P0 | NOT_RUN |
| AC-API-005 | 回复约束 | Given DeepSeek 返回文本，When 文本为空、超过最大长度或包含配置的禁止词，Then 阻止发送并进入人工处理状态 | P0 | NOT_RUN |
| AC-REP-001 | 陪聊人设 | Given 用户配置称呼、关系、语气和回复长度，When 生成回复，Then 输出应体现这些配置且不泄露系统提示词 | P0 | NOT_RUN |
| AC-REP-002 | 上下文使用 | Given 当前会话包含最近对话，When 对方提出依赖前文的问题，Then 回复应引用已加载上下文而不是只回答当前单句 | P1 | NOT_RUN |
| AC-REP-003 | 敏感内容保护 | Given 生成内容涉及转账、验证码、密码、身份证、付款链接或高风险承诺，When 回复进入发送前检查，Then 阻止自动发送并请求人工确认 | P0 | NOT_RUN |
| AC-SND-001 | 输入框定位 | Given 已绑定 QQ 窗口，When 准备发送，Then 输入框位置必须通过固定锚点和相对区域重新确认，不得使用过期缓存坐标直接发送 | P0 | NOT_RUN |
| AC-SND-002 | 输入内容确认 | Given 回复文本已生成，When 写入输入框，Then 必须截图确认输入框中的文本与待发送文本一致；不一致时不得按发送键 | P0 | NOT_RUN |
| AC-SND-003 | 发送确认 | Given 已按发送键，When 消息区更新，Then 必须识别到新的自己发送气泡，才可标记发送成功 | P0 | NOT_RUN |
| AC-SND-004 | 发送结果不确定 | Given 无法确认是否发送成功，When 发送结果处于不确定状态，Then 程序必须暂停并等待人工处理，不得自动重发 | P0 | NOT_RUN |
| AC-SND-005 | 收件人锁 | Given 入站消息来自绑定联系人，When 发送任何回复，Then 目标会话 ID、标题校验结果和窗口句柄必须同时匹配，否则禁止发送 | P0 | NOT_RUN |

## 4. 状态与交互验收

程序至少包含以下状态：

| 当前状态 | 事件 | 下一状态 |
|---|---|---|
| UNBOUND | 输入名称并成功绑定 | READY |
| UNBOUND | 名称或窗口不匹配 | UNBOUND |
| READY | 启动 | MONITORING |
| MONITORING | 检测到新的对方消息 | GENERATING |
| GENERATING | DeepSeek 返回合法文本 | SENDING |
| GENERATING | DeepSeek 失败 | PAUSED |
| SENDING | 输入确认和发送确认成功 | MONITORING |
| SENDING | 发送结果不确定 | PAUSED |
| MONITORING | 标题变化、群聊、窗口遮挡或锁屏 | PAUSED |
| PAUSED | 用户手动恢复且前置条件满足 | MONITORING |
| 任意运行态 | 停止或急停 | STOPPED |

验收时必须逐项测试合法转换，并验证非法转换不会执行，例如：

- `UNBOUND` 不得进入 `MONITORING`。
- 标题不匹配时不得进入 `SENDING`。
- `PAUSED` 时不得生成新的自动发送。
- 发送结果不确定时不得进入 `MONITORING`。

## 5. 异常与恢复验收

| ID | 异常 | 期望处理 |
|---|---|---|
| AC-ERR-001 | QQ 窗口被最小化或遮挡 | 暂停；恢复可见后不得补发旧回复，除非用户手动确认 |
| AC-ERR-002 | Windows 锁屏或休眠 | 暂停；解锁后重新校验窗口、标题和上下文 |
| AC-ERR-003 | QQ 掉线或退出 | 暂停并显示错误；不得继续键鼠操作 |
| AC-ERR-004 | OCR 置信度低 | 不生成回复；记录低置信度画面和失败原因 |
| AC-ERR-005 | 消息区发生未知布局变化 | 不点击、不发送；进入暂停并要求重新校准 |
| AC-ERR-006 | 程序崩溃后重启 | 恢复上下文和去重指纹；不得重复回复崩溃前已确认发送的消息 |
| AC-ERR-007 | 切换联系人后切回目标联系人 | 必须重新识别标题；未重新确认前不得发送 |

## 6. 非功能验收

| 类别 | 验收目标 |
|---|---|
| 检测性能 | 新文字消息出现到写入待回复队列的 p95 不超过 2 秒 |
| 发送性能 | DeepSeek 返回合法文本后，到开始执行粘贴动作的 p95 不超过 1.5 秒 |
| API 超时 | 单次 DeepSeek 请求超时时间可配置；默认不超过 60 秒，超时不得发送 |
| 稳定性 | 在目标 Windows 环境连续运行 30 分钟、处理至少 100 轮消息，不发生崩溃、卡死或重复发送 |
| 资源占用 | 连续运行 30 分钟后，进程内存不超过 1.5 GB，空闲 CPU 平均不超过 10% |
| 安全 | API Key 不以明文出现在代码、配置文件、日志、截图或错误提示中 |
| 隐私 | 截图默认只驻留内存；关闭程序后不保留原始屏幕截图 |
| 数据 | 本地上下文默认保存在项目数据目录的 SQLite 数据库中；卸载或清空时可由用户删除 |
| 可访问性 | GUI 主要操作可使用键盘完成；错误不得只用颜色表示；焦点顺序与控件关系明确 |
| 兼容性 | 在当前验收机器、固定 QQ 版本、固定分辨率与缩放比例下通过全部 P0 用例 |

## 7. 测试数据与证据

验收至少准备以下数据：

- 一个目标私聊联系人。
- 一个非目标联系人或群聊，用于验证绑定拦截。
- 中文、英文、数字、换行和长文本消息样本。
- 表情包、图片或纯表情消息样本。
- 对方连续发送两条消息的样本。
- 自己主动发送消息的样本。
- DeepSeek 正常、超时、401、429 和 5xx 测试结果。
- 锁屏、最小化、窗口切换和 QQ 掉线测试。

验收证据必须包括：

- GUI 绑定成功和失败截图。
- 消息检测前后截图。
- DeepSeek 调用结果和耗时日志。
- 输入框写入确认截图。
- 发送确认截图。
- 去重、暂停和恢复日志。
- 30 分钟运行记录和资源占用记录。

## 8. 通过门槛

只有同时满足以下条件才算验收通过：

1. 所有 P0 用例结果为 PASS。
2. P1 用例不存在影响正常陪聊流程的失败。
3. 不存在导致发错人、重复发送、泄露 API Key 或绕过收件人锁的缺陷。
4. 30 分钟稳定性测试和至少 100 轮消息测试通过。
5. GUI 中 `目标用户名称` 输入、绑定、错误提示和状态显示全部可现场演示。
6. 非文字消息能被识别为事件，但不会进行表情或图片语义识别。
7. 程序在 API 失败、OCR 失败和发送结果不确定时均采取停止或人工接管。
8. 用户本人明确回复“通过”或“批准”。

## 9. 未决事项

- 验收机器的 QQ 版本和显示缩放比例需要在开工前固定。
- 对方的私聊标题可能存在备注名和昵称差异；验收时以 QQ 当前显示标题为准。
- “回复风格”和“禁止词”默认值需要由用户确认。
- DeepSeek 模型名和最大回复长度需要由用户确认。
- 非文字消息是否允许发送通用回应，默认关闭，等待用户明确决定。
